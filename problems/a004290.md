## Plain statement

For each n take the smallest positive multiple of n written with only the digits 0 and 1 (for n=3 that is 111). The claim: for every n below 99...9 (k nines), this multiple is smaller than the one for 99...9, which is 9k ones.

## Definitions

a(n) = least m>0 with n dividing m and every decimal digit of m equal to 0 or 1 (a(0)=0 in Lean). Known: a(10^k - 1) = (10^(9k)-1)/9 (nine k ones). Claim: for every k and every n < 10^k - 1, a(n) < a(10^k - 1). First 15 terms a(1..15) = 1, 10, 111, 100, 10, 1110, 1001, 1000, 111111111, 10, 11, 11100, 1001, 10010, 1110. a(n) is found by breadth-first search over remainders mod n, appending digit 0 before digit 1.

## Checked so far (Python, 2026-10-04, not a proof)

Python BFS: k=1..5 exhaustive, i.e. n<9, 99, 999, 9999, 99999: 0 violators; a(99999) = 45 ones as predicted (k=5 run took about 13 minutes). No failure.

## Attack ideas

Hunt for n < 10^k - 1 whose 0/1 multiple has at least 9k digits (k=6 needs 10^6 BFS runs: fine in C/WASM); or prove a uniform bound that every n < 10^k - 1 has a 0/1 multiple with fewer than 9k digits (pigeonhole gives only n digits).

## Risks and notes

Infinite family; a proof needs a new bound on 0/1 multiples. Lean statement quantifies over all k, matches docstring (k=0 vacuous).
