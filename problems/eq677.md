## Plain statement

A finite 'multiplication table' (a set with some rule combining two elements into one) that obeys the law x = y*(x*((y*x)*y)) for all x,y; must it also obey x = ((x*x)*x)*x? The project guesses no, which needs a finite table obeying the first law but not the second.

## Definitions

Finite magma (G,*) given by a table G x G -> G. Equation 677: for all x,y: x = y*(x*((y*x)*y)). Equation 255: for all x: x = ((x*x)*x)*x. Claim (to prove or refute): every finite magma satisfying 677 satisfies 255. Linear models x*y = a*x + b*y + c (mod n) satisfying 677 exist for n=5 (a=2,b=4,c=0), 7, 11, 13, 19, 31, 35, 37, 41, 43, 49, 55.

## Checked so far (Python, 2026-10-04, not a proof)

Python backtracking: order 1 (trivial) is the only magma satisfying 677 at orders 1-4 (exhaustive; none of order 2, 3, 4). Order 5 search hit the 100 s cap after 12 million nodes (not exhaustive). 501 linear magmas Z_n (n<=60) satisfy 677: all satisfy 255. No counterexample.

## Attack ideas

Finite counterexample search with a SAT/constraint solver for orders 5-9 (equation 677 pins the table down strongly), or a proof that 677 forces 255 in finite magmas (e.g. via a left-multiplication permutation argument).
